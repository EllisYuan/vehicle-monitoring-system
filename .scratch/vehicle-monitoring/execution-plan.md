# 车辆监控系统执行清单（串行版）

依据：`spec.md` 与 `issues/` 各票的 `Blocked by`。一次只做一票，做完合入 main 再切下一票。

## 排序原则

1. **关键路径前置。** `05 → 06 → 07 → 08 → 12 → 13 → 18 → 23 → 27` 共 9 票决定全部时间。前 8 票排在清单最前，任何一票出问题都在最早的时点暴露。
2. **依赖未满足的不排前面。** 每票只在 `Blocked by` 全部 resolved 后开始，不提前写"占位实现"。
3. **同一共享文件的票不背靠背。** `router.ts` 与 `AppShell.vue` 是高频冲突文件，含前端页面的票尽量间隔安排，避免连续改动同一处。
4. **长时间验收单独安排时段。** 24（100 终端压测）、25（30 天量级容量）、23（故障注入）各占独立时段，不与日常开发穿插。

## 每票工作流

1. 从 main 最新 tip 切 `feat/ticket-NN-<slug>`，票改 `Status: claimed`。
2. `/tdd` 逐切片实现，先红后绿，不预填验收。
3. 跑本票验证：
   - 后端单票：`mvnw.cmd -B -pl server -Dtest=<X>Test test`
   - 全量含浏览器：`mvnw.cmd -B "-Dvms.browser-tests=true" test`（PowerShell 下必须给 `-D` 参数加引号，03 曾因未加引号报 `Unknown lifecycle phase`）
   - 前端：`pnpm --dir web typecheck` / `lint` / `build`
4. `/code-review` 两轴审阅（Standards + Spec），修复后重跑验证。
5. 写 `.scratch/vehicle-monitoring/evidence/NN-verification.md`，勾选**实际通过**的 AC，票改 `resolved`。
6. 合入 main。
7. 更新 `.scratch/vehicle-monitoring/README.md` 的「当前进度」。
8. `/clear` 后开始下一票。
