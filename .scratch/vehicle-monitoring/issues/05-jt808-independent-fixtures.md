# 05: JT/T 808-2019 独立报文验证

Status: open
Labels: ready-for-agent
Type: task
Blocked by: 01

## What to build

在 protocol 模块实现 JT/T 808-2019 核心子集 codec，并以有标准条目依据的独立 hex fixture 验证预期，不能只用共享 codec 自生成样例证明正确。支持 ID 为 0x0100、0x8100、0x0102、0x0002、0x0003、0x0001、0x8001、0x0200、0x0704、0x8300、0x8202；覆盖：2019 消息头（消息 ID、属性、终端手机号 BCD、流水号、包封装项按需）、消息体转义与 XOR 校验、BCD/GBK 编解码、定长与变长 TLV、头长度与体长限制。只支持不分包、不加密、消息体不超过 1023 字节；0x0704 每包最多 20 点且实际长度合法。fixture 须注明标准条目或样例出处；凡字段、修改单或枚举尚待权威资料核对的，明确标记 blocked 并列出待核字段，不凭模拟器与 server 共享 codec 互测宣称通过，也不生成“权威”假证据。坏帧、未知消息与越界长度安全处理：可识别时规范拒绝，无法安全识别时丢弃记录。

## Spec coverage

- 主：[AC07](../spec.md)；US87、US36 的协议部分。
- 次：US25 的报文基础；I8 协议子集与长度限制。
- 复验：06 起实际 TCP 接入依赖本票 codec，但独立 fixture 仍须保留参与后续验证，不能被端到端通过替代；本票不以 06 尚未实现而阻塞。

## Acceptance criteria

- [ ] 独立 hex fixture 覆盖 2019 消息头与转义/XOR 校验并通过
- [ ] BCD、GBK、TLV 编解码与独立预期字节一致
- [ ] 单包超过 1023 字节被拒绝，分包与加密消息可解释拒绝
- [ ] 0x0704 项数 ≤20 与长度双重校验生效
- [ ] 坏帧、未知字段、越界长度安全处理，不崩溃不拼接假 ACK
- [ ] fixture 标注标准条目/出处；共享 codec 生成物不作为唯一依据
- [ ] 待核字段以 blocked 明确记录，不写“通过”

## Scope boundaries

- 不做 TCP listener、会话、注册鉴权与数据库（06）；不做 JT/T 809、1078、分包重组、旧版 808 或加密。
- 本票不产生业务页面；模拟器 CLI 属 06。
- 协议字段未核清时只阻塞受影响消息，不阻塞已核清部分，也不伪造标准结论。

## Validation

- 以 protocol 单元测试运行独立字节 fixture，记录测试命令、依赖版本与逐条结果。
- 对无法核对的字段给出 blocked 清单与实际资料/错误证据，不以内部编码结果反证标准正确。
- 记录状态与证据位置；不得预填通过。
