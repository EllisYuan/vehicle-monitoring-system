# 车辆监控系统 Spec

Status: open
Labels: ready-for-agent
Type: spec

## Problem Statement

一家中小型道路货运企业管理多个车队，需要在桌面浏览器中查看车辆运行位置与通信状态，回看历史轨迹，发现超速、离线、定位异常和围栏进出，记录人工处置，并追溯终端通信及指令结果。车队长只能访问授权车队数据，不能依靠前端隐藏菜单防止越权。

当前仓库只有设计与 agent 文档，没有业务工程、migration、现存测试或实际运行证据。项目必须在单人约 10 周的毕业设计预算内形成可部署、可重复演示、可测试的闭环，而不是仅展示模拟地图动画或档案 CRUD。论文中的实现、测试和性能结论应由实际证据支持。

本 spec 将已逐轮确认的 Q1–Q50 与整合设计转为实现及验收基线，不代表功能已经实现、测试已经通过，也不自动授权开始业务编码。整合稿中明确标注的工程默认值在本文继续以默认值表达，不伪称为逐项确认的外部标准。

## Solution

构建面向单企业、多车队的模块化单体系统：Vue 桌面 Web 提供监控与管理两种布局，一个 Spring Boot 进程提供 HTTP、WebSocket 与 Netty TCP 接入，独立 Java CLI 模拟终端通过 JT/T 808-2019 核心子集发送实际 TCP 报文。

主要业务链路为：管理员维护档案和关联，模拟终端注册鉴权，位置与相应业务状态可靠持久化，WebSocket 推送地图与报警变化，用户查询轨迹、配置围栏、处置报警或发送两类指令，统计与导出按相同权限与口径读取数据。MySQL 保存业务事实，Redis 保存登录会话与可重建缓存。故障时必须明确显示失败或数据陈旧，避免向终端、浏览器或论文材料报告虚假成功。

交付包含应用、独立模拟器、数据库 migration、单机部署配置、可重复场景、测试和实际验证记录。设计容量为 100 终端、正常每 10 秒上报一次，默认在线保留 30 个日历日轨迹；具体硬件和性能结果在执行验收时记录。

## User Stories

### 登录与权限

1. 作为管理员，我希望首次部署时自行配置初始管理员凭证，以便系统不依赖公开默认密码。
2. 作为系统使用者，我希望通过账号密码登录并进入实时监控，以便开始当班工作。
3. 作为系统使用者，我希望退出、修改密码或会话到期后原会话失效，以便旧页面不能继续访问业务。
4. 作为管理员，我希望创建和停用账号、重置密码，以便维护独立且可追溯的操作身份。
5. 作为管理员，我希望给每个账号分配一个固定角色，以便统一控制功能权限。
6. 作为管理员，我希望给车队长分配一个或多个车队，以便准确限定数据范围。
7. 作为监控员，我希望查看全企业监控数据并执行授权作业，以便处理日常监控事件。
8. 作为车队长，我希望只看到授权车队的数据，以便管理职责范围内车辆。
9. 作为管理员，我希望停用或撤权后 HTTP 和现有 WebSocket 均及时生效，以便旧订阅不能继续获取越权数据。
10. 作为系统使用者，我希望重复登录时旧会话收到明确提示并失效，以便知道哪个会话有效。
11. 作为系统使用者，我希望连续登录失败触发可见的临时锁定，以便系统限制密码猜测。
12. 作为管理员，我希望登录与关键写操作有不含凭证的审计，以便追溯事件而不泄露密码或鉴权码。

### 档案与历史关联

13. 作为管理员，我希望维护车队的编号、名称和启停状态，以便组织车辆归属。
14. 作为管理员，我希望维护车辆及所属车队，以便监控数据具有明确业务对象。
15. 作为管理员，我希望预登记终端并绑定车辆，以便未知终端不能自动获得接入资格。
16. 作为管理员，我希望任一时刻车辆与终端最多一对一绑定，以便位置不会同时归属两辆车。
17. 作为管理员，我希望换绑时断开旧会话并保留生效区间，以便之后补传的旧位置仍归属原车辆。
18. 作为管理员，我希望维护司机编号、姓名、联系电话、所属车队和状态，以便联系车辆关联人员。
19. 作为管理员，我希望给车辆维护一名当前关联司机并保存历史，以便报警能解释事件发生时的关联关系。
20. 作为监控员，我希望报警显示当时的关联司机而不是当前司机，以便后续换关联不会改写历史。
21. 作为监控员，我希望不能确定车辆或司机历史关联时看到未关联或异常记录，以便系统不猜测身份或归属。
22. 作为管理员，我希望转队保留历史车队归属，以便补传和历史权限不会按当前档案误判。
23. 作为管理员，我希望有历史引用的档案通过停用保留，以便轨迹、报警和处置记录仍可解释。
24. 作为车队长，我希望司机电话按已确认规则掩码，以便只显示职责所需信息。

### 终端接入与位置可靠性

25. 作为模拟终端操作者，我希望完成注册、鉴权、心跳、位置上报与注销，以便验证真实 TCP 通信流程。
26. 作为管理员，我希望未知、停用、未绑定或鉴权失败的终端被拒绝，以便接入受到控制。
27. 作为模拟终端操作者，我希望位置持久化成功后才收到成功应答，以便成功应答代表数据已被可靠接收。
28. 作为模拟终端操作者，我希望 ACK 丢失后重传同一位置不会重复入库，以便网络重试不会污染轨迹与报警。
29. 作为管理员，我希望同终端同秒不同内容的位置保留冲突证据，以便系统不静默覆盖已接收事实。
30. 作为监控员，我希望历史补传补全轨迹但不使车辆图标回退，以便当前位置保持单调更新。
31. 作为管理员，我希望非法时间、越界坐标和无法解析归属的数据记录异常原因，以便定位接入问题。
32. 作为监控员，我希望定位无效时通信仍可被识别，但无效坐标不参与地图和围栏计算，以便区分在线与定位正常。
33. 作为模拟终端操作者，我希望批量位置只有在各项均已保存、幂等存在或保存异常后才收到成功应答，以便整包应答具有明确含义。
34. 作为管理员，我希望数据库故障或处理队列满时系统不返回假成功，以便终端可以按有界重试规则恢复。
35. 作为管理员，我希望新连接鉴权后旧连接失效，以便旧应答不能完成新会话的指令。
36. 作为模拟终端操作者，我希望不支持的分包、加密或消息得到可解释处理，以便区分永久拒绝与可重试故障。

### 实时监控与地图

37. 作为监控员，我希望在地图和列表中按车队、车辆和状态筛选，以便快速定位需要关注的车辆。
38. 作为监控员，我希望查看位置、速度、方向、ACC、定位状态和最后更新时间，以便理解车辆运行情况。
39. 作为监控员，我希望分别查看最后通信与最后有效定位时间，以便不把终端在线误认为位置新鲜。
40. 作为监控员，我希望位置变化合并推送而新报警尽快提示，以便监控页面及时更新且不无限积压消息。
41. 作为系统使用者，我希望断线、自动重连和数据陈旧状态可见，以便判断页面数据是否仍在更新。
42. 作为系统使用者，我希望重连重新获取快照和报警列表，以便断线期间的变化不会永久遗漏。
43. 作为车队长，我希望地图、列表、详情、统计和订阅均遵循相同授权，以便不存在其他入口绕过权限。
44. 作为系统使用者，我希望底图加载失败时仍能看到车辆列表及错误提示，以便识别外部地图故障。
45. 作为管理员，我希望在线底图的服务地址、图层和 key 可配置，以便按使用条件部署或更换供应商。

### 历史轨迹

46. 作为监控员，我希望按一辆车和不超过 24 小时的时间范围查询轨迹，以便回看一次作业过程。
47. 作为监控员，我希望跨日查询仍受保留期和数据权限控制，以便历史访问与正常查询一致。
48. 作为监控员，我希望播放、暂停、拖动及使用 1/2/4/8 倍速，以便检查重点时段。
49. 作为监控员，我希望数据缺失、无效定位形成明确断点，以便不把补画直线误认为真实行驶。
50. 作为监控员，我希望抽稀保留首尾、分段和重要事件关联位置，以便在点数受控时仍保留关键信息。
51. 作为监控员，我希望必要点超限时收到缩小范围的提示，以便系统不悄悄删除重要边界。
52. 作为管理员，我希望默认保留今天及此前 29 天轨迹，以便控制毕业设计环境的数据量。
53. 作为管理员，我希望降低保留期前预览删除范围并确认，以便避免普通配置变更立即删除历史。
54. 作为管理员，我希望分区维护失败有可见告警和记录，以便及时发现写入或清理风险。

### 报警与处置

55. 作为管理员，我希望配置全局默认与车队覆盖两级报警规则，以便不同车队使用合适阈值。
56. 作为监控员，我希望连续超速确认后形成一个持续事件，以便每次位置上报不重复生成报警。
57. 作为监控员，我希望异常恢复与人工处置分别显示，以便处理完毕不会掩盖持续异常。
58. 作为监控员，我希望离线判定排除未接入、停用和主动注销等状态，以便不把正常管理操作当通信故障。
59. 作为监控员，我希望定位无效和已支持的 GNSS 故障原因明确，以便区分位置质量问题。
60. 作为监控员，我希望终端报告报警保留来源，以便不把终端判断写成平台独立验证。
61. 作为监控员，我希望查看报警时间、位置、关联司机、规则及处置历史，以便核查事实。
62. 作为监控员，我希望将待处理报警领取为处理中并登记已处理或误报，以便形成操作留痕。
63. 作为车队长，我希望只读查看授权范围内报警和处置历史，以便了解车队情况。
64. 作为管理员，我希望并发判定不能生成多个同维度持续报警，以便恢复操作准确作用于原事件。
65. 作为监控员，我希望应用重启不自动清除 ACTIVE 报警，以便监控中断不会被误记为恢复。

### 电子围栏

66. 作为管理员或监控员，我希望绘制和编辑圆形、多边形围栏，以便定义监控区域。
67. 作为管理员或监控员，我希望绑定车辆并选择进入、离开事件，以便监控相应区域变化。
68. 作为监控员，我希望首次定位仅建立内外基线，以便接入时已经在区域外的车辆不被记成刚刚离开。
69. 作为监控员，我希望连续 3 点确认状态变化且边界算内，以便减少边界抖动误报。
70. 作为管理员或监控员，我希望围栏形状或绑定变更后重新建基线并审计，以便配置变化不伪造进出事件。
71. 作为车队长，我希望只看到与授权车辆相关的围栏和绑定，以便围栏列表不泄露其他车队车辆。

### 指令

72. 作为管理员或监控员，我希望向在线终端发送文本信息，以便验证平台下行通信。
73. 作为管理员或监控员，我希望请求临时高频位置跟踪，以便短时观察车辆变化。
74. 作为管理员或监控员，我希望区分提交、发送、终端应答成功、失败和超时，以便不把提交成功当执行成功。
75. 作为监控员，我希望指令关联终端、连接代次、流水号和应答消息类型，以便迟到或旧会话应答不会误匹配。
76. 作为监控员，我希望离线终端不自动排队、超时不自动重发，以便避免不可控重复文本或指令。
77. 作为模拟终端操作者，我希望文本和跟踪指令产生可验证应答及行为变化，以便能够端到端验收。

### 统计、导出与交付

78. 作为管理员或监控员，我希望查看车辆总数、在线、离线及其他状态，以便了解当前监控覆盖。
79. 作为系统使用者，我希望查看今日报警、待处理报警和处理率，以便安排处置工作。
80. 作为系统使用者，我希望按日期、类型与车队查看聚合，以便识别异常分布。
81. 作为系统使用者，我希望处理率使用同一创建时段的报警作为分母，并说明包含误报，以便指标可复算。
82. 作为有导出权限的使用者，我希望导出车辆、报警和处置记录，以便保留工作台账。
83. 作为车队长，我希望导出同样被服务端授权限制，以便筛选参数不能越权。
84. 作为管理员，我希望导出最多 1 万行、字段脱敏且记录筛选与行数，以便避免大查询和敏感信息外泄。
85. 作为开发与验收人员，我希望用固定种子和场景配置重复运行模拟器，以便比较修复前后行为。
86. 作为开发与验收人员，我希望从空数据库执行 migration、单独生成模拟档案并启动系统，以便部署可复现。
87. 作为开发与验收人员，我希望独立报文字节校验 codec，以便共享 codec 的双方不会互测掩盖同一错误。
88. 作为开发与验收人员，我希望执行数据库故障、Redis 重启、应用重启、终端与浏览器重连场景，以便验证恢复语义。
89. 作为开发与验收人员，我希望测量 100 终端 30 分钟的正确性与浏览器更新延迟，以便给性能结论提供真实证据。
90. 作为论文作者，我希望分别记录目标、实测、失败、未执行和模拟数据，以便论文材料可追溯。

## Implementation Decisions

### I1. 范围、架构与交付

- 单企业、多车队、桌面 Web；Windows 开发，Linux 单机 Docker Compose 交付。
- 模块化单体，单个后端实例同时提供 HTTP、WebSocket、Netty TCP；模拟器独立进程。
- Maven 聚合 protocol、server、simulator；server 与 simulator 依赖 protocol，protocol 可依赖 Netty，不能依赖 Spring、数据库或业务 Service。不建立独立 common 模块。
- server 按 identity、fleet、terminal、access、telemetry、track、alarm、geofence、reporting、audit、infrastructure 分职责，内部按需分层。Channel 归 access，业务经接口协作，不从 TCP 或 controller 绕过权限/事务服务调用 Mapper。
- Web 一次登录、监控与管理两种布局，按 feature 组织业务；地图实例、车辆图层、轨迹与绘制集中管理。
- 部署默认后端 HTTP 8080、TCP 9000，由 Nginx 承接 Web 与 HTTP/WS；MySQL/Redis 不对公网开放，开发端口映射只绑定 localhost。外部部署使用 TLS，localhost 开发可使用 HTTP。

### I2. 技术栈与版本验证

- JDK 21 LTS、Spring Boot 4.1.x、Netty；Netty 优先由 Boot dependency management 管理。
- MyBatis-Plus 与 Sa-Token 使用 Boot 4 starter；springdoc-openapi 3.x；MySQL 8.4 LTS、Flyway versioned SQL；Redis 保存登录会话和派生缓存。Sa-Token 不再叠加 JWT。
- Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios、OpenLayers、ECharts，Composition API 与 script setup；pnpm lockfile、vue-tsc、ESLint。
- Excel 工程默认 Apache POI。Maven Wrapper、依赖锁定与镜像版本记录可复现构建。
- 初始化时验证并锁定 patch、Node/pnpm 与镜像版本，不将旧调研版本直接视为可构建组合。系列不兼容时提交明确阻塞和设计修订，不静默换栈。
- migration 管正式结构与升级，模拟档案与容量数据由显式命令生成，不能混入正式 migration。

### I3. 角色、操作与字段权限

固定角色 ADMIN、MONITOR、FLEET_LEADER；一个账号一个角色，车队长可授权多个 fleet_id。角色功能由代码定义，无菜单/按钮权限设计器。

| 操作 | 管理员 | 监控员 | 车队长 |
|---|---|---|---|
| 监控、轨迹、报警、统计、档案查看 | 全企业 | 全企业 | 授权车队 |
| 车辆、报警、处置 Excel | 全企业 | 全企业 | 授权车队 |
| 报警处置、文本/跟踪指令 | 可 | 可 | 不可 |
| 创建/编辑/停用围栏、绑定车辆 | 可 | 可 | 不可 |
| 报警规则、基础档案、历史关联维护 | 可 | 不可 | 不可 |
| 账号授权、系统参数、系统操作/登录审计 | 可 | 不可 | 不可 |

- 所有列表、详情、聚合、导出、WS 订阅和输出在服务端检查功能权限与数据范围，不能仅依赖菜单或客户端传来的 fleet_id。
- 车队长可见报警处置历史，但不可见系统审计；围栏只显示与授权车辆有关的信息，不能泄露其他绑定车辆。
- 司机仅采集 driver_no、name、phone、fleet_id、status；关联历史单独保存，不采集证件号或影像。管理员/监控员按职责看完整 phone，车队长掩码中间四位。
- 三类 Excel 均不含司机 phone、精确 lng/lat 或凭证，车牌正常显示；授权地图/轨迹返回必要坐标。

### I4. 账号与会话

- 8 小时绝对到期，不随活跃续期；单账号单有效会话。后登录、退出、停用和改密/重置使旧会话失效。
- 普通用户修改本人密码，管理员重置；初始管理员凭部署配置一次性建立，无固定默认密码和公网自助注册。
- 同账号连续失败 5 次锁定 10 分钟，成功后重置；工程增加来源速率限制，避免凭证猜测和锁定滥用。
- 后续 HTTP 请求使用当前授权，WS 最迟 5 秒停止旧授权推送并关闭或重建订阅。HTTP/WS 对账号停用和会话到期同样生效。
- HTTP 使用 Sa-Token 随机会话 token；长期凭证不进 URL/日志。WS 默认使用登录后取得的短时一次性 ticket 握手，ticket 也应从日志中抹除。
- Redis 重启可能要求重新登录，但不能丢失已提交业务数据；Redis 残留值不能作为当前终端连接权威。

### I5. 数据模型与历史关系

22 张设计表按职责落地，表数不是验收指标；纯支撑结构可在保持语义时调整并同步设计。所有表名/字段均为待 migration 验证的设计字段，不是已部署 schema。

| 职责 | 设计表 |
|---|---|
| 身份与授权 | sys_user、sys_user_fleet |
| 基础档案 | fleet、vehicle、driver、terminal |
| 生效区间 | terminal_vehicle_binding、vehicle_driver_binding、vehicle_fleet_history |
| 位置与异常 | track_point、vehicle_last_position、telemetry_anomaly |
| 报警 | alarm_rule、alarm、alarm_handle_log |
| 围栏与判定状态 | geofence、geofence_vehicle、vehicle_monitor_state |
| 指令 | command_log |
| 可靠通知 | notification_outbox |
| 审计与配置 | audit_log、system_config |

- username、fleet_code、plate_no、terminal_no 等业务标识按设计唯一；有引用的档案停用，ID 不复用。
- 任一时刻车辆/终端一对一，车辆至多一名当前关联司机。绑定区间使用 effective_from/effective_to 的左闭右开区间，变更不得倒填，锁定相关记录并由数据库约束当前唯一性。
- 换绑前停收旧会话，gps_time 决定历史车辆、车队和关联司机；无法唯一归属写异常，不用接收时的当前关系推测。
- 同一持续报警固定开始时的 driver_id，不因关联变化回写。关联司机不是实际驾驶身份认证。
- track_point 与 alarm 保存 fleet_id_at_event，转队保存 vehicle_fleet_history。工程默认轨迹同时要求当前车辆访问权和事件车队权限；新车队不可因此读转入前轨迹。历史报警/处置按事件车队授权保留，但不附加当前越权位置或电话。车辆转队后旧队不得继续收到新位置。

### I6. 轨迹分区、唯一性与异常

- track_point 按 gps_time 定位日期日分区；主键与唯一键包含 gps_time。唯一位置键为 terminal_id 与 gps_time，查询索引包含 vehicle_id、gps_time。
- 同键位置规范化内容一致为重传；payload_hash 参与比对，不把 serial_no、received_at 或包顺序当作位置内容。需要保存的 TLV 属于内容，未知 TLV 必须长度安全跳过。
- 同秒不同内容保留首条正常位置，后到内容写 telemetry_anomaly；不覆盖、不进实时判定。正常或异常记录提交后才返回成功；数据库故障不能声称已保存异常。
- 不使用 INSERT IGNORE 吞掉截断、分区缺失或其他 SQL 错误，仅处理预期唯一键冲突。
- 结构合法但定位无效的点可存 track_point，lng/lat 为 NULL、locate_state 标记无效，保存必要受限原始内容用于比对；不伪造 0/0 或复用旧坐标。
- 默认按 Asia/Shanghai 日历日保留今天及此前 29 天。Flyway 建表及初始分区，应用默认预建未来 7 天并启动/每日巡检，清理过期分区记录范围和结果。
- 缩短保留期先预览删除范围及估算影响，经管理员确认再生效；维护失败告警。保留期外新上报记受限异常摘要，不重建过期轨迹分区。
- 报警、处置、绑定/关联历史与审计本期不自动清理，不删除仍被保留轨迹引用的历史关系。30 天不宣称满足真实运营全部监管期限。

### I7. 位置判定与 ACK 事务

- EventLoop 仅作网络分帧/反转义、长度/校验/版本及必要会话处理；MySQL、Redis 等阻塞访问进入有界业务执行器。
- 同 terminal_id 串行，换绑使用同一控制边界；同车状态以行锁/版本避免跨任务竞争。
- 一个数据库事务保存位置或异常、单调有效最新快照、由该点引起的报警/围栏状态以及待通知记录。提交后才回成功 ACK，随后刷新缓存和通知；缓存/WS 故障不能改变成功提交事实或拖住 ACK。
- 执行器满或数据库失败不回成功，可失败或断开以便有界重试；内存待处理数据不是已持久化成功数据。
- gps_time 为协议 UTC+8 定位时刻，received_at 为接收时刻，统一 Asia/Shanghai，不能互换。
- 时差 received_at−gps_time 在 −30 秒至 60 秒内才可成为实时候选；显式补传或旧于已处理点只补历史。工程默认容差内未来点仅作为历史轨迹持久化，不推进当前水位/报警/围栏，时间追上后也不追认或自动补算，避免一个未来点冻结后续正常位置；未来超过 30 秒记异常。
- 定位无效可更新有效通信时间，实时无效状态参与定位异常规则，但不更新有效位置快照或计算超速/围栏。
- 0x0704 先验证全包结构/项数/长度，再一个事务处理。成功表示每项正常保存、已幂等存在或异常已保存；失败不形成可见的部分成功数据。

### I8. 协议子集与终端生命周期

| 用途 | message ID |
|---|---|
| 注册/应答 | 0x0100、0x8100 |
| 鉴权 | 0x0102 |
| 心跳/注销 | 0x0002、0x0003 |
| 双向通用应答 | 0x0001、0x8001 |
| 位置/批量 | 0x0200、0x0704 |
| 文本/临时跟踪 | 0x8300、0x8202 |

- 只支持 2019、不分包/不加密，消息体不超过 1023 字节，0704 每包最多 20 点且实际长度仍须合法。
- 预登记、启用、绑定的终端才可接入；注册不自动建档。鉴权码由平台注册响应提供，服务端保存摘要比对，不明文展示或日志输出。
- 校验、转义、GBK/BCD、变长 TLV、消息头版本与长度须严格处理。未知/不支持消息只在可信头部及身份可确定时回规范拒绝，无法安全识别的帧丢弃记录，不拼接假 ACK。
- 当前 Channel 与 connection_epoch 只由 access 进程内注册表确认；新鉴权替换旧连接，旧会话应答不能完成新指令。
- 合法注销按协议应答后撤销连接代次，在途指令 FAILED，显示主动断开，不新造通信故障报警。非主动断线立即停止可发送性，离线事件仍按通信阈值判定。
- 具体 2019 鉴权字段、文本类型、0704 枚举/应答、8202 停止格式与修改单需权威资料和独立 fixture 核对。未核清不得凭互测宣称标准正确，应标记受影响实现阻塞。

### I9. 实时推送与 outbox

- REST 提供快照，WS 提供变化；位置最多每 2 秒合并为每车最新点，新报警/处置提交后尽快通知。位置源正常为 10 秒，不伪装每 2 秒获得真实定位。
- 连接前鉴权，订阅与输出按最新权限过滤；慢客户端有界缓冲，显示断线并重连，不无限堆积。
- frame 含事件标识、聚合对象、version、server_time，旧版本不覆盖新状态；重连恢复订阅后再次查询快照/报警，补上初始查询至订阅之间的窗口。
- notification_outbox 持久重试，event_id 唯一；状态 PENDING/RETRY/DONE/DEAD。工程默认最多 10 次后 DEAD 并告警，可审计重投；DONE 7 天清理，DEAD 不自动删。
- 位置通知为可合并的每车最新版本，worker 清理必须限定其已读版本，不能清掉并发更高版本。报警/处置独立事件不合并丢失。
- 不承诺每浏览器持久投递或恰好一次。MySQL/REST 是状态依据，客户端去重，重连校正；Redis 最新位置可以重建，当前连接不能由旧缓存恢复为在线。

### I10. 报警与处置

- 平台类型包括超速、离线、定位无效/GNSS 异常、围栏进出；终端来源仅映射已核对的报警位。PLATFORM 与 TERMINAL 保留来源，不无依据合并。
- 全局默认与车队覆盖两级，车队覆盖优先；不做车型/单车层级。工程规则参数按版本保存，事件保留当时规则依据。
- 默认限速 80 km/h，连续 3 个有效实时点超限成立；工程默认连续 3 个有效点 ≤阈值恢复，无额外滞回。候选点间隔 >30 秒重计，不能清掉 ACTIVE。
- 定位无效连续 3 个实时位置成立，连续 3 个有效点恢复；无效坐标不计入超速成立/恢复或围栏。
- 已鉴权、启用且曾接入的终端 180 秒无有效通信成立离线，有效重连通信恢复；未接入、主动注销、停用、解绑不伪造新的通信故障。应用启动 180 秒宽限。
- condition_state 与 handle_status 分开：持续异常 ACTIVE/RECOVERED，瞬时围栏等事件用 EVENT，无虚构恢复；处置 PENDING→PROCESSING→HANDLED/IGNORED，终态不重新打开。新异常周期建新事件，不引入人工归档。
- 相同车辆、类型、来源与相关规则/围栏业务维度最多一条 ACTIVE，数据库唯一约束与行锁保障；恢复按 alarm_id 和当前状态条件更新，不能误关新周期。
- 每次处置记录操作者、时间、状态变化和备注；异常恢复不自动处置、人工处理不自动恢复。

### I11. 围栏

- 圆形/多边形，持久几何 WGS84，地图按实际投影显示。服务端与页面校验相同合法几何；工程默认圆半径 10–100000m、多边形 3–20 顶点，拒绝自交、退化和越界。
- 车辆绑定且启用时监控进入/离开；边界算内。首次有效实时点仅建立基线，连续 3 点确认新的内外状态后生成一次事件；相邻有效点 >30 秒重置候选。
- 重启、形状或绑定改变重新建基线并审计，不推算停机进出，不清除其他持续报警/处置。历史点不改变当前围栏状态。
- 距离使用米或适当区域投影，不直接把经纬度差或屏幕像素作为真实距离。

### I12. 轨迹与地图

- 每次一辆车、最长 24 小时、最多 2000 展示点，允许跨日查询但执行保留和权限限制。
- 无效定位或有效点间隔 >30 秒形成分段；先分段后抽稀，工程默认 Douglas-Peucker 米制容差从 10m 调整。保留首尾、分段边界和重要事件关联位置；必要点仍超限要求缩小范围，不能静默截断。
- 原始轨迹不改；实时尾迹也不跨断点伪连。回放按 gps_time 播放/暂停/拖动、1/2/4/8 倍速，断点显示缺失且不跨段插值。无原始轨迹批量导出。
- 地图 OpenLayers，天地图 WMTS 为首选；道路与中文注记、服务 CRS、attribution/key 配置核对后接入。开源引擎不代表底图免费或允许离线抓取。
- 数据保持 WGS84，明确实际 CRS 与 Web Mercator 的投影转换；不自动套 GCJ-02 偏移。底图失败显示错误和可用列表，不能将静态截图计作地图实时验证。

### I13. 指令

- 文本 0x8300、临时跟踪 0x8202；工程默认文本最多 100 汉字且按真实 GBK 字节校验，跟踪间隔 1–60 秒、有效期最多 3600 秒，不超过单包容量；停止形态待标准核对。
- 状态 SUBMITTED/SENT/ACK_SUCCESS/FAILED/TIMEOUT；成功只表示终端应答，不表示司机阅读。
- 发送必须有当前已鉴权 Channel，离线不排队；关联 terminal_id、connection_epoch、serial_no 与应答消息类型，默认 30 秒超时，不自动重发。手工重试创建新记录；迟到应答留痕，不将过去超时改写为当时成功。
- 页面提交与通信结果分开。模拟器接收指令、正确应答并改变临时上报行为，验收不能只检查指令日志创建成功。

### I14. 统计与导出

- Asia/Shanghai，今日从 00:00 至当前；车辆总数、在线数、离线数、今日报警数、PENDING 待处理数、PROCESSING 处理中数分别呈现。
- 在线只计启用且绑定在线终端的车辆；离线只计曾接入且满足离线条件者；未接入/停用/主动断开/启动待确认另列，在线加离线不必等于总数。
- 历史报警按 start_time 进入选择时段；处理率分子为同批报警中当前 HANDLED/IGNORED，分母为同批总数，零显示“—”，标明包含误报。
- 日期趋势、类型分布、车队聚合均按同一权限与事件归属；当前车辆统计按当前档案，历史报警按 fleet_id_at_event。
- Excel 只车辆、报警、处置三类，同步最多 10000 数据行；超限报错要求缩小范围，不能静默截断。使用字段白名单、文本单元格与一致筛选/排序，防公式注入。
- 审计记录操作者、条件、行数和结果；生成失败不返回伪成功或残缺成功文件，导出正文不写审计日志。

### I15. 故障恢复、模拟器和验证前提

- MySQL 恢复报警、必要判定状态和最新有效位置；既有 ACTIVE 不因重启变 RECOVERED/HANDLED。候选计数重建，围栏重新建基线，180 秒启动宽限。
- 停机不离线重算报警；补传只补轨迹。记录监控中断，页面显示陈旧，不把旧缓存当新定位。
- Java CLI 配置服务器、车辆数、正常 interval、固定路线与随机种子；场景覆盖正常、停车、超速、围栏、定位异常、重连、补传、重复/冲突、ACK 丢失及两类指令。
- 工程默认等待 ACK 5 秒、最多 3 次重试，可为故障场景调整；区分临时与永久失败，永久拒绝停止重试。模拟器复用 codec，但测试 fixture 独立。
- 不申请账户、不把 key、token 或个人真实数据写仓库；天地图账户与网络条件在地图接入前验证。版本兼容、协议字段核对与证据属于明确前置工作，未验证项不能写“通过”。

## Testing Decisions

### 测试边界与判据

主要测试边界沿用 Q38/Q47 和已确认链路：向实际 TCP listener 输入独立报文或受控模拟终端消息，从公开 HTTP/WS 输出、终端应答及业务可追溯结果验证行为。尽量通过这一完整边界覆盖事务、权限与恢复，不 mock 每个内部 Service 或以私有方法调用作为验收。

补充两类边界：codec 使用独立预期字节覆盖生产/模拟器共享错误；浏览器覆盖地图交互、回放、断线提示、权限切换与真实文件下载。几何、抽稀、状态规则必要时以稳定公开模块接口作精确例子测试，避免大量端到端用例耗时推进到真实 180 秒；可控制业务时钟和测试依赖故障，不改变生产业务语义、不暴露测试后门。

当前仓库无测试先例。具体测试工具在初始化时选择并验证，优先使用能运行真实 MySQL 8.4 的集成环境验证分区、唯一性和事务，不能用内存 SQL 数据库替代这些数据库验收。第三方底图加载与账户额度单独手工/浏览器核验，不能因为测试替身成功就宣称真实地图验证通过。

数据库查询用于核对已承诺的持久性、幂等和原子性，不断言 Mapper 调用次数、线程名或内部对象布局。每个用例应能明确判断通过/失败并保存必要证据。

### 可检查验收场景

| ID | Given / When | Then |
|---|---|---|
| AC01 | 空数据库与非默认管理员配置，启动应用并执行升级 | 结构可重复升级；管理员可登录；没有自动生成模拟业务数据；凭证不出现在日志 |
| AC02 | 三角色和两个车队，车队长修改 URL、查询参数、导出或 WS 订阅跨队 | 服务端拒绝；列表/详情/聚合/围栏绑定不泄露其他车队；操作矩阵逐项成立 |
| AC03 | 有效会话被停用/改密/新登录替换/到期/撤权 | 后续 HTTP 不再使用旧授权；旧 WS 最迟 5 秒停止；8 小时绝对期限不滑动 |
| AC04 | 登录失败累计至5次并推进时间 | 锁10分钟；锁定前成功重置计数；错误响应不泄露凭证 |
| AC05 | 并发绑定同终端/同车辆、司机关联或转队 | 不形成重叠当前关系；历史区间可追溯；既有引用不被物理删除 |
| AC06 | 终端换绑后补传旧时刻位置，或新队查询转入前历史 | 旧位置归属旧车辆/车队；报警关联当时司机；新队不能读未授权历史；不明归属写异常 |
| AC07 | 独立 hex fixture 含转义、BCD、GBK、长度、TLV与2019头部 | 编解码符合独立预期；坏帧、未知字段和越界长度安全处理；无本 codec 自生成 fixture 作为唯一依据 |
| AC08 | 未登记/停用/未绑定/未鉴权终端发送业务消息 | 按可信身份和协议拒绝，不自动建档、不维护在线、不写正常车辆位置 |
| AC09 | 正常0x0200，持久提交前暂停/失败数据库 | 提交前无成功 ACK；失败无正常提交；恢复后有界重传成功且数据可追溯 |
| AC10 | ACK丢失，重传同定位体但改变报文流水号 | 仅一条正常位置和一次相应事件变化，重复返回成功，不重新报警 |
| AC11 | 同终端同秒不同内容，上报两次或并发 | 首条保留；冲突证据持久化后应答；快照/报警不被冲突点改变 |
| AC12 | 0704混合新点、重复、冲突，或包结构/事务中途失败 | 成功包全部可解释；结构/数据库失败不部分提交后回成功；点数与体长度均受限 |
| AC13 | 历史、乱序、未来容差、超过未来容差及保留期外数据 | 合法历史补轨迹不回退实时；容差内未来点不冻结正常流；非法/超界记录原因，不意外重建过期分区 |
| AC14 | 3个实时无效定位点后3个有效点 | 定位异常成立/恢复；无效点lng/lat为空，不进地图/超速/围栏；回放出现断点 |
| AC15 | 位置成功提交后Redis或WS不可用，随后恢复 | 成功ACK不依赖缓存；持久业务不丢；快照可重建；通知可重试，重连可校正 |
| AC16 | 同事件重复enqueue、worker崩溃、位置并发更高版本、永久失败 | 不重复业务事件；高版本标记不被旧worker清除；最大10次后DEAD且可见；不声称每浏览器恰好一次 |
| AC17 | 新连接替换旧连接、旧会话应答或合法注销 | 旧代次失效，不能完成新指令；注销正确应答并收尾在途指令；缓存不能伪造Channel |
| AC18 | 连续3点超速、持续超速、3点恢复、间隔中断或并发判定 | 同维度最多一个ACTIVE；候选中断不抹除ACTIVE；恢复针对正确alarm_id，无逐点新增 |
| AC19 | ACTIVE事件人工HANDLED，或RECOVERED事件仍PENDING | 两种组合合法；每次处置留日志；无自动归档/假恢复；新周期新事件 |
| AC20 | 终端未接入、失联、停用、主动注销、服务重启与重连 | 仅适用失联满180秒新建离线；启动180秒宽限；重连恢复；未接入/管理操作不伪报警 |
| AC21 | 围栏首次点、边界点、3点跨界、抖动、>30秒间隔、编辑/重新绑定 | 边界内；首次/变更只基线；确认后一次事件；补传不改变围栏；其他ACTIVE不清除 |
| AC22 | 单车≤24小时跨日轨迹，含无效点/缺口/大量重要边界 | 返回≤2000展示点；断点不伪连；关键点保留，必要点超限提示缩小范围，原始数据未改 |
| AC23 | 浏览器回放播放/暂停/拖动/各倍速并跨断点 | 时间轴与车辆位置一致，断点显示缺失，无跨段连续插值；不出现轨迹批量导出 |
| AC24 | 向在线模拟器发送文本/跟踪，另测离线、超时、迟到/错误应答 | 终端实际接收并改变行为；状态区分正确；30秒超时、不自动重发；旧epoch不误配；不表述司机已读 |
| AC25 | 构造跨日期与不同处置状态报警、零分母及多车队 | 今日/趋势按Asia/Shanghai和start_time；处理率可复算含误报；各状态不硬凑总数；权限先过滤 |
| AC26 | 三类导出各≤10000行、>10000行、公式样式文本、越权筛选 | 正常文件与页面条件一致；超限明确失败；无phone/精确坐标/凭证；文本不执行公式；审计有条件/行数/结果 |
| AC27 | 保留期边界、预建失败、缩短保留期未确认/确认 | 日分区范围正确；失败告警；未确认不删；清理不毁保留轨迹所需历史；未自动清理业务审计 |
| AC28 | 应用带ACTIVE报警重启，停机中有车辆运动，后补传 | ACTIVE与处置保留、候选重建；不猜进出、不补算停机报警；旧位置陈旧可见 |
| AC29 | WS初次快照与订阅之间发生变化、重连、慢客户端、旧版本帧 | 再次快照/列表补齐，旧版本不覆盖；缓冲有界，连接状态可见，撤权不泄漏 |
| AC30 | 天地图真实key/图层/CRS与部署网络，另测网络失败 | 正常底图和中文注记可用且attribution正确；坐标对齐有证据；失败显示错误及列表，不使用截图冒充实时 |

| AC32 | 记录硬件/网络/版本，运行100终端、10秒间隔、30分钟 | 按实际发送与成功ACK核对唯一持久结果，理论约18000点不是固定实测数；接收至浏览器应用更新p95目标≤3秒 |

| AC34 | 新Linux单机按交付说明部署，执行migration、seed和CLI | 可完成启动、登录、通信、地图及场景验证；所有手工账户/key前提明确，不提交真实凭证 |

### 测试模块与证据

- protocol：独立输入字节与预期结果；记录标准条目/样例出处及待核字段，避免循环证明。
- identity/fleet/terminal：真实HTTP权限、并发关联、会话与字段脱敏；包含旧授权WS。
- access/telemetry/alarm/geofence：TCP到持久结果和公开输出，受控时钟、并发、回滚、断线与恢复。
- track/reporting：真实MySQL索引/分区查询、过滤、分段、点数、统计公式、导出文件内容。
- web/map：关键浏览器行为与错误状态，应用更新延迟测量不能只取服务端发送时间。
- outbox/deploy/simulator：重试、毒事件、重启恢复、空环境安装与场景重现。

每条验收记录状态为通过、失败、未执行或仅静态检查之一，并附命令/操作、配置、版本、时段、期望与实际结果及证据定位。不得预填通过。功能与性能测试均在实现后执行；本次生成 spec 只验证文档覆盖与一致性。
