### 容量目标（Q8）

以 100 辆模拟车辆同时连接、每辆正常每 10 秒上报一次位置为容量设计与性能验收基准，平均约 10 条位置上报/秒。若全天持续上报，约产生 86.4 万条位置记录/天；这属于容量估算，未进行性能实测。验收还需覆盖集中连接、重连与短时密集上报。数据保留时间与是否分区待定。

### 客户端与运行目标（Q9、Q10）

正式交付端为桌面浏览器 Web，兼顾常见笔记本分辨率；手机端专门适配、App 和小程序留到后续。采用 Windows 本地开发、Linux 单机 + Docker Compose 部署，保留本机演示路径；本期不承担 Kubernetes、集群部署与高可用建设。服务进程划分与具体工程结构待定。

### 协议实现路线（Q12）

自行实现 JT/T 808-2019 必要子集的 codec 与会话流程，包括必要消息的编码、解码、转义、校验及注册鉴权；使用 Netty 处理 TCP 通信。本期不承诺旧版协议兼容、JT/T 809 级联与 JT/T 1078 视频。具体消息清单、异常处理、与模拟器的代码共享边界待定；codec 验证需包含独立报文样例，避免服务端与模拟器共享错误而互测通过。

## 已确认：第三轮 Q13–Q21

### 架构（Q13）

采用模块化单体：一套 Vue 前端，一个 Spring Boot 后端进程同时提供 HTTP API、WebSocket 与 Netty TCP 接入；模拟器作为独立程序运行。后端本期只部署一个应用实例，业务按职责划分模块，网络处理与数据库操作使用不同执行线程。MySQL 与 Nginx 纳入部署方案；缓存用途、Maven 模块和目录细节尚未确定。

### 角色与数据权限（Q14）

| 角色 | 职责 | 数据范围 |
|---|---|---|
| 管理员 | 维护档案、规则、围栏、账号权限，查看与操作全部业务 | 全企业 |
| 监控员 | 实时监控、轨迹查询、报警处置、授权指令下发 | 全企业 |
| 车队长 | 查看车辆、轨迹、报警和统计 | 被授权的车队，可为多个 |

司机为业务档案，不提供登录账号。合并原系统管理员与企业管理员，不保留调度员角色。详细权限矩阵、账号与角色关系、权限变更行为待定。

### 关联司机（Q15）

车辆可人工指定一名当前关联司机，并保留关联变更记录。报警保存生成时的关联司机，后续更换关联不回写已有报警。普通位置报文不证明实际驾驶员身份；本期不实现排班、多人轮班识别或真实驾驶员身份认证，界面与论文使用“关联司机”。

### 报警范围（Q16）

必交付五组：平台超速、通信离线、定位无效/GNSS 异常、围栏进入/离开、终端报告的已支持报警标志。完成判定、去重、恢复与人工处置；详细阈值与状态机待定。终端报告的疲劳报警可以展示，但不代表平台实现疲劳算法。持续驾驶时长推算、平台疲劳驾驶判定、夜间禁行、停留超时暂不作为必交付功能。

### 电子围栏（Q17）

支持圆形、多边形绘制编辑、车辆绑定及平台判定进入/离开事件。以状态变化产生事件，不因持续在围栏外而逐点重复产生离开报警。本期不做围栏限速、停留计时或终端围栏下发。边界点、去抖、首次定位与补传处理待定。

### 轨迹保留与回放（Q18、Q19）

默认保留 30 天供在线查询，保留天数可配置；清理过期数据应有明确配置与操作记录。这属于毕业设计策略，不宣称满足真实运营的全部监管保存要求。全天持续上报的 30 天估算约 2592 万行，不代表已生成这些数据或已验证性能。

每次回放一辆车，单次查询最多 24 小时；服务端控制数据量，前端按定位时间播放，支持暂停、拖动及 1/2/4/8 倍速。长时间数据缺失需展示断点，不能以连续动画掩盖。抽稀、点数上限、原始点导出与跨天交互待定。

### 指令（Q20）

只实现文本信息下发与临时位置跟踪，由模拟器验证应答。区分已提交、已发送、终端应答成功、失败或超时；终端应答不等于司机已阅读文本。本期不做远程断油断电、任意参数修改或任意原始报文发送。message ID、字段、应答与超时语义待协议清单核对。

### 统计与导出（Q21）

统计包含：车辆总数、当前在线数/离线数、今日报警数、待处理报警数、报警处理率、按日期报警趋势、按类型报警分布、按车队车辆在线情况与报警数量。支持车辆档案、报警记录、报警处置记录 Excel 导出。本期不提供里程、油耗、利用率或司机安全排名统计。时间口径、分母、权限过滤与导出限制待定。

## 已确认：第四轮 Q22–Q30

### 工程结构（Q22、Q23、Q24）

单仓库管理全部工程，根 `pom.xml` 聚合 `protocol/`、`server/`、`simulator/` 三个 Maven 模块，另有 `web/`、`deploy/`、`docs/`、`.scratch/`、`GLOSSARY.md`、`README.md`。依赖为 `server → protocol`、`simulator → protocol`；`protocol` 不依赖 Spring、数据库或业务 Service。协议测试保留独立报文样例，不建立独立 common Maven 模块。

`server` 按 `identity`、`fleet`、`terminal`、`access`、`telemetry`、`track`、`alarm`、`geofence`、`reporting`、`audit`、`infrastructure` 组织业务能力，模块内部按需分层。HTTP 与 TCP 入口共用业务能力，业务 Service 不直接持有 Netty Channel。

前端为一套应用、一个登录入口、监控与管理两种布局，登录后默认实时监控。管理员可进入两种布局，其他用户按权限进入相应功能；服务端同时执行操作权限和数据权限校验。按 `features/` 组织页面、API、类型和状态；地图实例、车辆图层、轨迹图层与围栏交互集中到地图模块。

### 权限细节（Q25）

固定三类角色，一个账号一个角色；车队长可关联多个车队。管理员分配角色与车队范围，角色功能权限由代码定义，不做任意编辑的角色/菜单/按钮权限设计器。车队长只查看和导出授权范围数据，管理员或监控员按操作权限执行处置、配置与指令。账号停用或车队授权变化后，HTTP 请求和 WebSocket 订阅必须重新执行权限检查，具体失效时限待定。

### 终端与司机历史关联（Q26）

同一时刻车辆与终端最多一对一绑定，保留带生效时间的历史；换绑前先断开旧会话。历史位置按事件时间查找绑定，例如换绑后补传换绑前的位置仍归属原车辆；不能明确归属的数据进入异常记录，不更新当前位置。

关联司机保留生效时间，报警按事件发生时间解析关联司机，无法找到则显示未关联，不猜测身份。该时间口径细化 Q15：历史报警不随之后的换绑或司机关联变化回写。

### 位置处理可靠性（Q27）

报文必要校验后交给有界业务执行器处理，位置成功提交 MySQL 后才向终端返回处理成功。队列满或写入失败不返回成功，记录原因并按约定失败处理，由模拟器验证重传。数据库层保证位置幂等；历史补传可以补全轨迹，但不能回退最新位置、驱动当前围栏状态或重新播放实时报警。幂等键、事务边界、批量策略与恢复细节待定。

### 报警生命周期（Q28）

分开记录异常状态 `ACTIVE/RECOVERED` 与处置状态 `PENDING → PROCESSING → HANDLED/IGNORED`；不具备恢复语义的终端事件单独展示。持续异常更新同一事件，保存开始、最后发生、恢复时间；处置记录操作人、时间、备注，不另设人工归档步骤。终端报告与平台判定保留来源，不能确认同属一个事件时不强行合并。

### 规则作用域与默认值（Q29）

规则只支持全局默认与车队覆盖两级，不做车型或单车覆盖。默认位置 10 秒、心跳 60 秒；已鉴权启用终端连续 180 秒无有效通信判离线，未接入终端标未接入。默认超速阈值 80 km/h，可按车队修改，成立与恢复均连续 3 个有效实时定位点确认。连续 3 个无效定位点触发定位无效报警，恢复也需确认。正常重启不立即给全部车辆生成离线报警。以上为业务默认值，不表述为统一法定阈值；恢复滞回与中断规则待定。

### 围栏语义（Q30）

圆形/多边形边界算内；首次有效实时点只建立基线，不产生进出报警。连续 3 个有效实时点确认内外变化才生成一次事件，候选期间相邻有效点间隔大于 30 秒重新计数。围栏形状或绑定变化后重新建立基线并记录操作，历史补传不改变当前状态。本期只表达进出事件，不做启用时存量违规检查。

## 已确认：第五轮 Q31–Q38

### 后端与构建（Q31）

采用 JDK 21 LTS、Spring Boot 4.1.x、Netty（优先服从 Boot dependency management）、MyBatis-Plus Boot 4 starter、Sa-Token Boot 4 starter、springdoc-openapi 3.x、Maven 与 Maven Wrapper。常规查询使用 MyBatis-Plus，轨迹批量写入、历史关联与统计 SQL 按需显式编写。Sa-Token 管理登录会话，不另加 JWT。以上为已选兼容系列，具体 patch 版本需在创建工程后通过 dependency resolution、构建、启动验证再锁定；官方适配包不等于本工程已验证。

### MySQL 与 migration（Q32）

采用 MySQL 8.4 LTS 与 Flyway versioned SQL migration，空数据库可升级至当前结构；建表、索引及后续 schema 变更由 migration 管理。演示数据由独立命令准备，不混入正式 migration。旧 `schema.sql` 仅作参考，按本次范围重新设计。分区、幂等与关联历史约束待定。

### Redis（Q33）

引入 Redis，只用于登录会话、最新位置等可重建运行缓存及必要短期状态。MySQL 保存轨迹、报警、处置、绑定历史和指令事实；Redis 不作为轨迹/报警唯一存储或幂等唯一保障。Redis 重启不丢已保存业务数据，登录会话可能失效并要求重新登录；当前连接状态以实际进程连接为依据。本期不引入 Kafka 或 RabbitMQ，后台可靠性通过数据库记录与恢复流程落实。

### 前端（Q34）

采用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios、OpenLayers、ECharts；Composition API + `<script setup lang="ts">`，pnpm 与 lockfile，`vue-tsc`、ESLint 静态检查。HTTP API TypeScript 类型优先从后端 OpenAPI 生成，WebSocket 另有契约。管理页复用组件，监控布局单独设计，不采用包含大量无关业务的后台模板；具体兼容版本待工程验证。

### 底图（Q35）

天地图 WMTS 为首选，OpenLayers 加载道路与中文注记。接入前核对账户条款、attribution、额度与开发/部署网络加载效果，未承诺免费额度足够、未执行 key 申请或付费操作。服务地址、key、图层通过环境配置提供，保留替换底图接口；CRS 按实际服务定义处理，不默认套用 GCJ-02。

### 实时与恢复（Q36）

REST 加载初始车辆快照，WebSocket 推送变化；位置最多每 2 秒合并一次、每车保留本轮最新点，新报警与处置事务提交后尽快推送。连接状态可见并自动重连，重连后重新查快照与报警列表；业务详情以数据库为准。HTTP/WS 均按当前权限过滤，停用、会话失效或授权变化时关闭或重建订阅；确切失效时限待定。位置源仍每 10 秒上报，界面展示最后定位时间。

### 模拟器（Q37）

Java CLI + 场景配置文件，支持固定场景与随机种子，不开发独立管理 UI。场景包括注册鉴权心跳、行驶停车超速围栏与定位异常、断网重连补传、重复与应答超时重传、文本与临时跟踪指令及应答。复用 protocol 生产 codec，但 codec 测试必须有非本 codec 生成的独立报文与预期字节。

### 验收目标（Q38）

100 终端、10 秒间隔、30 分钟，理论约 18000 点，按实际发送日志核对；已成功应答位置可追溯，相同报文重传不重复计入。记录硬件/网络条件后，从服务端收到有效位置到浏览器应用更新的 p95 目标不超过 3 秒，属于待实测目标。验证数据库短时不可用、Redis/应用重启、终端/WS 重连、跨车队查询/导出/订阅拒绝，以及空环境部署。保留实际结果、失败与环境记录，不预填通过；30 天容量查询测试另行准备，不能由 30 分钟测试外推。

## 已确认：第六轮 Q39–Q47

### 保留与分区（Q39）

`track_point` 按定位日期分区，默认保留 30 天；报警、处置、绑定历史与审计本期不自动清理。Flyway 管表结构与初始分区，应用维护未来分区和过期清理，维护失败应有可见告警并记录结果。降低保留时间需展示将删除的数据范围并经管理员确认生效，不能因普通参数修改而立即删除。不得删除仍在保留期内轨迹所需的历史关联。

### 幂等与数据质量（Q40、Q41）

同终端、同定位秒、同内容视为重传，成功应答但不重复轨迹/报警；同秒不同内容保留首条正常位置，后到内容与原因写异常记录，不覆盖位置、不驱动实时状态，异常记录成功保存后返回已接收避免无限重传。本期时间精度为秒，跟踪最短 1 秒，不支持同终端一秒多个不同正常点。

接收时距定位时间不超过 60 秒的点才可参与实时计算；显式补传与比已处理点更旧的点只补轨迹。定位无效保留报文状态并更新通信时间，不使用无效坐标更新地图、判超速或围栏。定位超前接收时间 30 秒以上、非法日期或越界坐标记录异常。地图分别显示最后通信、最后有效定位时间，在线、定位有效、位置新鲜分别表达。

### 重启与监控中断（Q42）

停机期间不补算实时报警。报警、处置、最新有效位置与必要判定状态从 MySQL 恢复；既有 ACTIVE 报警不因重启自动恢复或处理。连续点候选重计，围栏重新收到有效实时点后建立基线，不猜停机期间进出。启动 180 秒宽限后，再对未恢复通信的已接入终端按规则处理。记录停机/监控中断，旧位置不得显示为正在更新；本期不做离线报警重算。

### 终端准入与协议（Q43）

仅预登记且绑定车辆的终端可接入，不自动创建未知档案；平台管理鉴权码，页面与日志不明文展示。11 个 ID：0x0100/0x8100、0x0102、0x0002、0x0003、0x0001/0x8001、0x0200、0x0704、0x8300、0x8202。仅不分包、不加密消息体，批量同时受点数（初始最多 20 点）与编码后单包 1023 字节上限约束。不支持能力明确拒绝与记录；模拟器区分暂时故障和永久拒绝，不无限重试。具体字段以核对标准和独立样例为准，不宣称全标准支持。

### 查询展示（Q44）

单次回放最多返回 2000 个展示点，有效点间隔超过 30 秒则分段；抽稀不改原始数据，首尾、分段边界与重要事件位置优先保留。必要边界仍超上限时提示缩小范围，不静默丢弃关键点。断点明确展示，不画虚假连续路线；不增加原始轨迹批量导出。

### 安全与导出（Q45）

会话最长 8 小时，退出/停用失效；绝对或滑动期限还需最后确认。同账号连续失败 5 次锁 10 分钟，成功重置计数。权限变化后后续 HTTP 使用新权限，WS 最迟 5 秒停止旧范围推送并重新订阅。Excel 同步单次最多 1 万行，超限缩小筛选；与页面同权限，记录操作者、条件和行数；不导出凭证，司机联系方式按权限脱敏，具体字段在最后一轮明确。

### 统计（Q46）

统一 Asia/Shanghai，今日从 00:00 到当前时刻。在线数限启用车辆中已绑终端且在线者；离线数限曾成功接入且已满足离线条件者；未接入/停用另列，因此在线+离线不必等于总数。报警按开始时间计；处理率为所选创建时段内当前 HANDLED 或 IGNORED 的报警数/该时段报警总数，标明包含误报，分母零显示“—”。全部按数据权限过滤，页面与导出同口径。

### 事务与通知（Q47）

位置、最新快照、由位置引起的报警/围栏状态及待通知记录在同一数据库事务内完成。提交后才应答、更新缓存和通知；缓存/WS 失败不撤销提交，后台按持久记录重试必要通知，浏览器重连查询校正。推送携带事件标识或版本以去重，不承诺端到端只投递一次，不引入消息中间件。

## 已确认：第七轮 Q48–Q50

### 操作权限（Q48）

管理员操作全企业全部业务；监控员查看全企业实时、轨迹、报警、统计与档案，导出车辆/报警/处置，处置报警、下发两类指令、创建编辑停用围栏并绑定车辆。仅管理员维护报警规则、车队/车辆/终端/司机与关联、账号权限、系统参数及查看系统操作/登录审计。车队长只查看授权车队业务并导出三类记录，不处置、不下指令、不改配置。车队长只可见与授权车辆有关的围栏信息，绑定列表不得泄露其他车队车辆；可查授权范围内报警处置历史，但不可查全系统审计。轨迹只查询/回放，不导出。

### 司机与脱敏（Q49）

司机只采集编号、姓名、联系电话、所属车队、状态与车辆关联历史，不采集身份证/驾驶证号或证件影像。管理员/监控员在职责范围内看完整电话，车队长看中间四位掩码。所有三类 Excel 导出均不含司机电话、精确经纬度或鉴权凭证；车牌正常展示导出，授权地图/轨迹仍提供必要坐标。演示默认使用明确标注的模拟档案。

### 登录（Q50）

会话从登录成功起绝对 8 小时到期，不滑动续期；每账号一个有效登录，后登录撤销旧会话，旧 WS 最迟 5 秒关闭并提示。每人独立账号以便留痕；初始管理员通过首次部署配置设置，无固定默认密码。普通用户改自己的密码，管理员重置密码，重置撤销该账号已有会话。
