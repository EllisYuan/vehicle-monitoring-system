# 持久提交后应答并保存待通知记录

用户在 Q27、Q40、Q47 确认：定位或异常处理成功提交 MySQL 后才向终端返回成功；同终端同定位秒的相同内容按重传幂等，不同内容保留首条并保存冲突证据。位置、最新快照、由该点引起的报警/围栏状态及待通知记录使用同一事务，避免位置已成功应答而报警因进程中断永久丢失。

Netty EventLoop 与阻塞业务分离，Redis 仅承担会话和派生缓存；事务提交后更新缓存并通过轻量 outbox 重试必要通知。这个选择增加数据库状态与恢复逻辑，换取可验证的故障语义，并避免引入外部消息中间件。浏览器推送仍可能重复，以事件标识/版本去重，重连通过查询校正；不承诺浏览器端到端恰好一次投递。
